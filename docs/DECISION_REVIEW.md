# 决策审查（DECISION_REVIEW）

> 发版、改默认行为、改动导出能力，或任何**不可逆 / 影响用户已有数据**的操作之前，走一遍这份清单。
> 本文件由 `AGENTS.md`「改动纪律」与 README / CONTRIBUTING 引用，必须保持存在。

## 什么时候必须走

| 场景 | 是否必过 |
| --- | --- |
| 发布新版本（打 tag / 发 release） | 必过 |
| 修改导出产物（HTML / PNG）的结构或字段 | 必过 |
| 改默认模式、默认主题、默认示例数据 | 必过 |
| 改本地存储（`localStorage` key / 结构） | 必过 |
| 改 URL / 文件名 / 部署方式 | 必过 |
| 修 bug、改文案、补测试 | 不必，但需自测 |

## 清单（逐条回答，答不上来就别发）

1. **影响面**：谁会受影响？老用户升级后有什么变化？有没有人依赖旧行为？
2. **可回滚**：出问题怎么撤？是不是一条 `git revert` 就能恢复？涉及数据迁移的，回滚后老数据还能读吗？
3. **数据与隐私**：新增了网络请求、外链、统计或第三方服务吗？（本项目红线：不允许）
4. **兼容性**：iOS Safari / 微信内置浏览器 / 旧 WebView 上还能用吗？导出物在「断网 + 双击打开」下还成立吗？
5. **验证**：`node tests/logic.test.js` 过了吗？视觉改动有没有真机/浏览器截图？有没有在导出产物上实际点过？
6. **文档同步**：README / CHANGELOG / FIELDS / ARCHITECTURE / API 该改的改了吗？版本号三处（代码注释、`window.XYIntroCard.version`、CHANGELOG）一致吗？
7. **不可逆动作**：涉及删文件、覆盖用户数据、对外发布、花钱的服务，是否已征得用户同意？

## 记录

- 结论写进当次 PR / commit message（`feat:` / `fix:` 前缀 + 一段「为什么」）。
- 影响架构层面的决定，另开 `docs/adr/NNNN-*.md`（见 [ADR 目录](adr/)），本清单不替代 ADR。
