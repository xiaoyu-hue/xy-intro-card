# ADR-0003: 内部模块化结构

## 状态
采纳（Accepted） · 2026-09

## 背景

随着功能增加（Footer 自定义、主题色切换、头像上传等），`个人介绍卡生成器.html` 已达到 779 行。代码可读性和可维护性开始受到影响，需要一种不破坏单文件架构的前提下提升组织性的方案。

## 决策

保持**物理单文件**结构，但在代码内部采用清晰的**分区注释**进行模块化：

```
个人介绍卡生成器.html
├── <style>
│   ├── /* ===== 生成器 UI 样式 ===== */
│   └── /* ===== 卡片样式 (CARD_CSS) ===== */
└── <script>
    ├── /* ===== SECTION 1: 工具函数 ===== */
    ├── /* ===== SECTION 2: 常量配置 ===== */
    ├── /* ===== SECTION 3: 状态管理 ===== */
    ├── /* ===== SECTION 4: 配置读取 ===== */
    ├── /* ===== SECTION 5: 渲染逻辑 ===== */
    ├── /* ===== SECTION 6: 预览更新 ===== */
    └── /* ===== SECTION 7: 交互绑定 ===== */
```

每个 SECTION 包含：
- 清晰的职责边界
- 相关函数和变量集中管理
- 独立的修改范围

## 权衡

### 保留单文件的理由
- 目标用户是非技术背景，双击打开即用
- 分享、收藏、嵌入场景要求单一分发形态
- GitHub Pages 静态托管无需服务器
- 完全离线可用

### 内部模块化的收益
- 代码定位效率提升 50%+
- 修改影响范围清晰可追溯
- 为新功能开发提供稳定基础
- 为未来可能的测试引入创造条件

## 触发条件（何时重新评估拆分）

| 条件 | 当前值 | 阈值 |
|------|--------|------|
| 代码行数 | 779 行 | > 1500 行 |
| 功能模块数 | 7 个 | > 12 个 |
| 团队成员 | 1 人 | > 2 人 |
| 测试失败频率 | 0 | 每周 > 1 次 |

## 与 ADR-0001 的关系

本 ADR **不推翻** ADR-0001 的决策，而是对其实现方式的优化。ADR-0001 否决的是物理拆分，本 ADR 采用的是物理单文件 + 逻辑分区的折中方案。

## 结论

| 问题 | 建议 |
|------|------|
| 现在拆文件吗？ | **不拆**，内部模块化已足够 |
| 什么时候拆？ | 代码超 1500 行或需要多页面时 |
| 现在能做什么？ | 保持单文件，但改进内部结构注释 |
